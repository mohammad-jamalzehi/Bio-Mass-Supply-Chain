  33 ## Reproduce
  34 
  35 Use the pinned Phase 2 Python dependencies. Run from the repository root.
  36 
  37 ```powershell
  38 python -m pip install -r requirements-phase2.txt
  39 python -B -m unittest discover -s tests -v
  40 python -B -m optimization.annual --days 3 --time-limit 15
  41 python -B -m optimization.annual --days 7 --time-limit 30
  42 python -B -m optimization.annual --scenario gams-historical-inputs --time-limit 30 --output runs/gams
  43 python -B -m optimization.annual --scenario report-narrative-capacity --time-limit 30 --output runs/report-capacity
  44 python -B -m optimization.annual --scenario report-table-emissions --time-limit 30 --output runs/report-factors
  45 ```
  46 
  47 The [scenario file](../scenarios/annual.json) holds inputs separately from
  48 solver code. Feedstock lists are positional in this order: full truck volume,
  49 wet density, moisture, dry heating value, and price per dry tonne. Daily
  50 overrides use day numbers as strings and replace named fields. The report
  51 alternatives change one assumption at a time. Both retain the unconfirmed
  52 GAMS demand. The emissions alternative has no effect on the objective or
  53 constraints. Alternative optimal plans can still differ if there are ties.
  54 The scenario SHA-256 includes the effective inputs, assumptions and horizon.
  55 A shortened experiment imposes its final stock policy at the shorter cutoff.
  56 
  57 The CLI calls the unchanged sparse Phase 3 MILP across the requested days.
  58 In its dedicated process a scoped solver wrapper adds a time limit and retains
  59 the raw SciPy outcome. Prices are temporarily represented in thousands of
  60 source dollars to improve numerical summation and are converted back for audit
  61 and export. Negative solver values within the existing Phase 3 tolerance of
  62 zero are set to zero before audit. Larger violations remain visible. No
  63 physical constraint changes.
  64 
  65 For both optimal outcomes and time-limited incumbents, the audit checks each
  66 day's Phase 3 constraints, reconciles whole-horizon material balances by fuel,
  67 and independently recomputes cost, heat, and emissions. The solver objective
  68 must match the recomputed cost. On optimal termination the bound must match it
  69 too. A separate incumbent decoder reads the original Phase 3 variable order,
  70 checked against the Phase 3 plan on optimal runs.
  71 
  72 ## Exports and statuses
  73 
  74 Specify an output directory to produce `result.json` and `flows.csv`.
  75 JSON includes inputs and assumptions, scenario digest, solver version and
  76 elapsed seconds, objective, bound, gap, validation outcome, and audited
  77 plans when available. A null solver field means unavailable. CSV has one
  78 inventory/delivery row per fuel and day, one burn/heat row per plant and fuel
  79 per day, and one gas row per day. The gas row also carries the daily demand,
  80 cost, and emissions totals once. A run without an audited plan exports the
  81 CSV header only. The CLI returns 0 for an audited optimum and 2 for other
  82 outcomes after recording diagnostics. Runtime is machine-dependent.
